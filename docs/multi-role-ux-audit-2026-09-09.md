# eDoc 多角色表單與流程修繕

日期：2026-09-09。範圍：首頁、撰寫公文、電子用印、簽核紀錄、收發管理、系統設定。

## 測試方式與界線

使用隔離資料庫中的合成人員：一般員工、課長、部門主任、行政部門主任、總務、執行長；另以跨公司帳號確認拒絕存取。瀏覽器使用桌機 1440 × 1000 與手機 390 × 844 視窗。這不等同真實 Google 帳號登入、iPhone／Android 實機驗收，也沒有在正式站建立測試單、寄出公文或動用正式印章。

保留既有會計組織來源、角色權限、A4 限制、附件掃毒、印章版本綁定與核准後鎖定；政府正式交換仍停用。此次不需要資料庫 migration。

## 驗收紀錄

已完成相同合成資料的修正前後比較：72 個角色／頁面組合中，66 個可用頁面沒有整頁溢出或 window error，6 個未授權設定入口不暴露；12 組 PDF 文字保存與讀回、12 次舊 revision 409、12 次跨公司 403 通過。另有 4 組公文填寫旅程、36 個斷言（包含手機確認區實際邊界），以及隔離 PostgreSQL 的 18 個公文產出測試通過。

本機完整 Python／前端合約測試共 708 項：698 項通過、10 項環境限定測試略過（已啟用隔離 PostgreSQL gate）。PDF 編輯六組旅程 86 個斷言通過；scope／epoch 補強後，再跑員工桌機／手機 42 個斷言，全部通過。收錄與派發 16 組互動、39 個斷言通過。

發布仍須通過 GitHub CI。正式部署編號、CI 結果與版本雜湊另記於本次交付的驗收證據，不能以本文件的修正清單替代正式部署證明。

畫面與 JSON 證據位於本機 `/tmp/edoc-role-ux-evidence-20260909/`，不包含真實人員公文或正式憑證。`before-after.html` 為實際瀏覽器截圖比較，不是設計示意圖。

## 保留限制

- single-flight 防同畫面連點，不是跨裝置／跨分頁的伺服器冪等保證。遇不確定網路結果，仍應先查清單再決定是否重送。
- 內部回文與結案同時發生時，條件更新確保不會把案件重開；它不是跨多次 Storage／REST 呼叫的一筆交易，已開始的回文可能較晚完成留存。
- 用印送簽瀏覽器測試會攔截最後 POST，以驗證第一步不送出、第二步只發一次；完整後端鎖定與簽核則由隔離 HTTP 流程測試驗證。
- 真實 Google／Finance SSO、真實人員組織異動、手機實機及正式寄送仍需在有合法登入與業務資料的情境另行驗收；本次不冒用真實員工。

## 發布與回退

使用獨立 worktree，保留使用者原工作目錄。CI 通過後驗證 production 設定的未綁網域候選版本，再切換正式網域；比對 `index.html`、`app.js`、`styles.css` 雜湊，以及健康、就緒和匿名 API 拒絕結果。若候選版未通過則不切換。既有正式政府交換設定不變。
