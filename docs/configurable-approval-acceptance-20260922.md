# 電子用印與可設定簽核流程驗收

日期：2026-09-22。本紀錄為三角度改善前的隔離驗收快照；當時尚未發布正式前台或套用正式資料庫更新。後續發布條件及新增修繕見 [三種使用情境改善與發布驗收](20260922-three-perspective-release-acceptance.md)。

## 已完成

- 系統設定可依文件類型新增、刪除、排序簽核關卡，選擇組織職務或指定啟用的 Finance 人員。總務執行、申請人收件保留為系統階段。
- 設定只影響新送簽案件；已送簽案件保留當時流程、人員與文件版本。設定採版本衝突檢查，不覆蓋另一位管理者的修改。
- 目前簽核人可通過、退回上一關、通過後加簽；原申請人可在仍待簽核時抽單。第一關仍可退回申請人補正，開始用印後不能抽單。
- 抽單複製可編輯版本，重送完整重走簽核；原稿、舊版簽核及檢閱證據不覆寫。
- 修正抽單重送的雲端操作編號重複、歷史收件關卡誤選、加簽候選包含尚待簽人員、設定重試受伺服器時間影響等問題。
- 公文的指定簽核人維持同公司授權。上傳 PDF V2 的跨公司人員僅限已驗證的同一 Finance 租戶與有效公司、人員；跨公司、跨租戶限制不因新增設定而放寬。
- 未選文件類型時先聚焦欄位，不再將前置資料未填誤報為 PDF 損壞。沒有可用印章仍可上傳與編輯，但不繞過送簽時的有效印章檢查。
- 新增動作使用原子交易、精準關卡與版本檢查、可重試操作編號及稽核紀錄；資料庫缺新版 RPC 時 readiness 不會回報就緒。

瀏覽器以真正頁面操作完成上傳、中文文字編輯、放大小章、兩組不同位置騎縫章、保存重開、逐關檢閱原稿／編輯版並簽核。申請人、先前簽核人及最後簽核人都下載到相同雜湊的成品。流程設定、退回上一關、加簽、抽單重編重送也由瀏覽器操作，不以直接呼叫簽核 API 冒充 UI 驗收。

確認原稿位元組不變、原稿／編輯版／用印版雜湊不同；原文字與新增中文保留；8 個完整／騎縫章區域有實際印章像素，透明區不遮蓋底圖。手機欄位至少 16px、可操作按鈕至少 44×44px，無橫向溢出或未處理錯誤。

PostgreSQL 實測包含完整設定保存後自訂第一關送簽、審核完成、退回／加簽保留歷史、真正送簽→抽單→新代次重送→完成，以及同時通過與抽單只有一方成功。缺少檢閱證據、過期關卡、自簽、越權、偽造流程、用印開始後抽單及 RPC 權限漂移都會拒絕。
