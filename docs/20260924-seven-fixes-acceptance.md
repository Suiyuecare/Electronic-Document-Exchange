# 2026-09-24 簽核、案件清單與重新整理修正

## 範圍與限制

修正前一輪確認的七項問題，及同一流程交叉檢查發現的首頁漏列、舊總務寄發歸屬與非同步回應覆蓋問題。使用去識別化帳號、合成 PDF、測試印章與隔離資料庫驗證，不在正式案件注入失敗，不呼叫正式電子公文交換。

## 問題與驗收標準

| 問題 | 修正及通過條件 |
| --- | --- |
| 退回重送後，用印重試被舊簽核擋住 | 重試、完成用印與建立寄發均使用最新 workflow generation；舊總務無法重試，舊歷程不改寫；目前流程缺總務時拒絕，不回退舊人員 |
| 最新 300 件以外的待辦／紀錄漏列 | 授權候選篩選先於資料庫 keyset 分頁；1,000 件混合公司及 1,101 筆歷程不漏列；游標綁定使用者與篩選，無重複或跳號 |
| 收件確認可能只完成部分寫入 | 關卡、結案、實際操作者、流程紀錄與稽核紀錄共用交易；最後一筆 audit 寫入失敗時全部回復；六個併發確認僅一組完成紀錄 |
| 重新整理沒有真正讀取最新資料 | 桌機／手機觸發實際讀取、顯示忙碌狀態、成功後才回報；重複操作合併，失敗保留資料及未儲存輸入 |
| 印章 503 被當作無印章且無法重試 | 網路錯誤與空資料分離，失敗保留公司／已載入資料；重試與重新進入均可恢復，舊回應不能覆蓋最新狀態 |

| 跨秒確認後看不到實際收件人 | 新紀錄明確關聯 step_id、actor_id、log_id；舊資料僅以唯一可信證據顯示，不以原指派人冒充實際操作者 |

首頁分別讀取本人待辦及最近申請；載入件數明確標為「已載入」，不將第一頁當總數。逾期退回補正及授權用印重試也必須出現在待辦。案件詳情混入共享快取時，仍按目前頁籤重新分類。
