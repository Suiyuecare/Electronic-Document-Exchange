# 公文擬稿規則與驗收

適用：AI 主旨／說明生成及其本機備援；不改送審、發文、電子交換或人員權限。

## 教材依據

## 實作

`official_writing.py` 為無網路、無資料庫的純規則模組。既有 Responses API、環境模型設定、30 秒逾時、禁止重新導向傳輸及 audit 呼叫保留。

輸入沿用 `plainText`、`docType`、`recipient`、`attachments`（實際檔名字串陣列）；增加 `documentDate`、`issuerName`。`attachmentDetails` 保持使用者可編輯的字串，不能單憑此欄認定已上傳檔案。

輸出保留 `subject`、`body`、`model`、`usedOpenAI`、既有 `notice`；另回傳 `warnings: string[]`。所有規則均在單次呼叫內運作，沒有跨使用者草稿快取。

1. 先以正式、精簡主旨表明事項與請求；說明採實際需要的連續編號。
2. 日期只做等值格式轉換；不存在的日期不修正、保留原文並提示。
3. 引用未來的已完成事件，保留來源日期及文號，改成「所提供資料…尚待核對」並警示；正常的未來計畫不警示。
4. 模型結果檢查口語、空泛依據、編號、數字、日期、文號、計畫／完成狀態、常見人員變更姓名方向及附件宣稱。
5. 無已上傳附件不宣稱檢附；有附件保留實際檔名，不編造名稱及未知份數。
6. 模型不可用、格式錯誤或未通過品質檢查時，使用本機規則並明示「非 AI 生成」。品質失敗回傳待核對警示，audit 只記規則代碼而非草稿全文或上游錯誤內容。

## 已驗證與界線

`tests/test_official_writing_ai.py` 使用去識別化資料，所有 API 與 audit 均 mock。涵蓋截圖類型案例、未來日期、混合時序、姓名方向、金額千分位、附件、模型失敗、錯誤訊息去敏及呼叫間隔離。

規則檢查不是完整語意理解或外部事實查核。複雜案由、不同句子中的主詞與時序、法律或機關層級仍需承辦人審稿；不得對使用者宣稱 AI 保證內容正確或文件已獲核准。本機備援為可核對草稿，不保證任何自由文字皆能重組成最終發文稿。本輪未呼叫真實模型，模型寫作品質以強提示及可重現的 mock 回歸驗證，未宣稱已完成線上模型實測。
