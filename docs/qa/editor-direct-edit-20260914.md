# PDF 簡易直接編輯驗收

## 範圍與操作目標

沿用本機簡化版 `435bb1d`，將「先在表單輸入、再放到 PDF」改成直接在文件上輸入。參考 Smallpdf 的公開加字操作說明：<https://smallpdf.com/blog/add-text-box-to-pdf>。沒有將公司文件傳到 Smallpdf，也沒有使用其服務處理檔案。

主要任務：上傳 PDF → 點加文字或圖片 → 在文件上修改、拖曳 → 自動保存 → 預覽送簽確認版。

驗收標準：桌機及 390px 手機無整頁水平溢出；編輯控制至少 44px；手機文字輸入至少 16px；中文輸入法、Tab、Enter、Escape 正常；一次完成只產生一次歷程；空白新增、取消、未修改不產生版本；原稿、印章尺寸與送簽鎖定不變。

## 已實作

- 加文字：選工具後點 PDF，直接輸入；Enter 完成，Shift+Enter 換行；完成／取消按鈕支援手機。
- 修改新增文字：點選後「編輯文字」、文字工具點選既有文字，或連點兩次文字。
- 文字字級與顏色就在輸入區；其他位置、尺寸、透明度及圖層設定按需展開。
- 圖片在主工具列；已選物件提供複製一份、刪除、其他設定。
- 使用與後端相同的鎖版編輯字體與換行規則；較長文字自動增高，超過單頁則拒絕完成，不靜默截斷。
- 直接輸入是獨立暫存，不把半成品文字放入 manifest；確認後走既有 history／autosave 路徑。
- 保留多行與舊版最多 1,000 字、6–144 字級；未改內容不重新排版或消耗 revision。
- 文字落點考慮 0／90／180／270 度頁面旋轉；預覽文字基線經 PDF.js 頁面座標換算。
- 草稿／公司／登入切換清除失效暫存；正常 autosave 更新 revision 不會清掉正在輸入的字。
- 自動保存回傳時保留同一物件、同一草稿內正在輸入的位置數值；切換物件、草稿或唯讀狀態則重新載入正確值。
- 非同步字體載入完成後，不會在原稿／送簽確認版上重新畫出可編輯物件。

不包含 OCR、任意原始 PDF 字體的原地文字重排或個人電子簽名。既有安全取代、遮蔽、圖形、螢光、印章及騎縫章仍保留。

## 驗證與證據

- `tests/test_editor_inline_text.py`：直接編輯生命週期、IME、失焦、旋轉、換行、字體與範圍隔離。
- `tests/test_editor_simplified_controls.py`：主工具、可達性、歷程及 SVG 點選區。
- `tools/verify_editor_inline_text_browser.py`：合成員工／執行長、桌機／手機的直接輸入、修改、複製、刪除、圖片、後端讀回及 prepared PDF 文字完整性。
- `tools/verify_editor_correctness_browser.py`：圖片、刪頁、重開、精準位置、跨頁複製與產出檢查。

完整測試：1,024 項測試中 943 項通過、81 項需要指定資料庫／外部環境而跳過，零失敗；跳過項目不算已驗證。
文字與簡化工具重點回歸：53 項通過。

直接編輯瀏覽器旅程：151/151 項通過，涵蓋員工／執行長各自的桌機 1440×1000、手機 390×844。90 度旋轉頁面的新增文字落點差異小於 1px，且先驗證測試點不在既有文字點選區內，避免混淆新增與編輯。另一組輸出正確性旅程 30/30 項通過，包含自動保存期間精準座標欄位不被覆寫。

每組皆驗證真實 HTTP 上傳、後端草稿讀回、prepared PDF 兩頁保存與中文長文字尾碼完整。prepared PDF 另經 Poppler 渲染，已檢查桌機與手機輸出的換行、圖片與頁面內容。

Before 是同一工作樹的 `435bb1d` 靜態資產；After 每次驗收先凍結資產並記錄 SHA-256，避免混用施工版本。使用同一份兩頁合成 A4 PDF，無客戶姓名或合約內容。

## 發布邊界

這是本機實作與隔離驗收，尚未部署正式前台。沒有變更 API、資料庫、Storage、掃毒、正式 SSO、組織／簽核關係或印章權限。未送出正式申請、用印、寄送，也未連接正式電子公文交換。

手機是 Chromium 響應式模擬；沒有宣稱實機 iPhone／Android 或 Safari／Firefox 已驗收。正式部署需另行授權、CI 與部署後驗證。
