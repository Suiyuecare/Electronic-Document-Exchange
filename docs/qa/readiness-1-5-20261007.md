## 速度量測的界線

`tools/editor_latency_browser_acceptance.py` 僅接受 loopback fixture，產生不含個資的 PDF。
A4 測試刻意暫停真正的上傳請求，先實際加字，再放行並從伺服器讀回文字；
這證明可以開始編輯不依賴上傳完成，不是模擬成功 HTTP。上傳未完成時禁止送簽。
非 A4 須先上傳原稿並取得轉換確認，不能套用同一個上傳前可編輯承諾。
第一頁時間以真正 PDF canvas 繪製後的 animation frame 量測，另記模型初始化時間。

正式站唯讀單次樣本：入口 HTTP 200 約 464ms、health HTTP 200 約 592ms、
內部 readyz HTTP 200 約 1,606ms。這不是登入後工作區資料完成的量測，也不是 p95。
沒有宣稱所有工作區更新 0.5 秒或所有 PDF 2 秒無條件達標。

5. 人工核准後才提升正式 alias；比對提交 SHA／靜態檔 hash、內部 readyz、匿名拒絕及回退版本。

### 回退規則

- 提升前記錄既有正式 deployment／提交 SHA、source migration ledger 與可還原備份 receipt。
- 尚未產生交接業務寫入時，可回退前台 deployment；新增 schema 保留，不執行刪表或改寫歷史的逆向 migration。
- 已確認交接或建立關聯新案後，不能直接假設舊程式仍支援追蹤責任。先停止擴大開放與相關業務操作，保留原案／新案／責任鏈，修復或經人工審查的相容版本再恢復。
- 備份只先在隔離目標還原並比對完整性；不得為了回退而將舊備份覆蓋正式資料，抹除其後的簽核與寄送證據。

備份還原既有 receipt 不代表例行異地備份、金鑰交接或 Storage 平台重建均已完成。
完整靜態 UI 掃描仍有既有頁面／原生 JS 事件委派／生成檔的待核對項，不能聲稱全專案靜態符合性為零。
