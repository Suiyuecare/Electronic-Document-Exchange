# 四角色上線問題檢視

本文用員工、主管、總務、收到公文或合約的單位四個角度檢查 EDOC 上線前問題。

## 員工 / 申請人

- 主要問題：撰寫公文時不知道缺哪個欄位，送簽前未確認預覽，或離開頁面造成草稿遺失。
- 已改善：首頁顯示今天前三件事；撰寫頁改為填寫、附件、用印與預覽同頁；必要欄位有即時提示；輸入內容會先保護在本機草稿。
- 上線檢查：員工可用 `employee@suiyuecare.com` 或 `sales-assistant@suiyuecare.com` 登入，完成撰寫、預覽確認、送清稿與退回補正流程。

## 主管 / 簽核者

- 主要問題：主管若只看待簽核清單，容易漏掉逾期、退回補正、交換異常或核准後自動用印的責任。
- 已改善：首頁新增主管決策面板、風險排序、部門負載、簽核進度快照與角色待辦摘要。
- 上線檢查：主管可用 `director@suiyuecare.com` 登入，確認待簽核、退回補正、風險排序與簽核紀錄皆依角色顯示。

## 總務 / 收發用印

- 主要問題：總務同時負責收文、發文交換、用印、jAgent 狀態與憑證，若沒有優先排序會先處理到低風險案件。
- 已改善：首頁新增總務今日優先順序；公文收發保留待登錄、待分派、交換失敗與用印佇列；合約用印與 PDF 用印集中到總務處理。
- 上線檢查：總務可用 `edoc@suiyuecare.com` 登入，確認收文登錄、分派、發文查詢、交換失敗重送、合約用印與 PDF 押章流程。

## 收到公文或合約的單位

- 主要問題：部門收到公文或合約後，常不清楚目前在誰手上、下一步是辦理、簽核、補件、用印或歸檔。
- 已改善：首頁新增「收到公文或合約的單位」承接表，依單位彙整公文、合約、待辦數、風險數、目前關卡與下一步。
- 上線檢查：切換不同角色或帳號後，確認只看得到該部門、本人承辦、被授權或全公司範圍內的承接資料。

## 仍需正式上線前確認

- Supabase 正式資料庫、RLS 與 private storage 必須完成，不可讓 production 依賴 Vercel `/tmp` SQLite。
- 正式簽章、TSA、OCSP、CRL、物件儲存與防毒端點仍需由實際服務提供。
- jAgent 正式 provider 必須等機關提供 SDK/API/封包規格後實作；目前不得自行假設交換格式。
- Email、LINE 與監控告警通道需完成實測，否則退回、逾期與交換失敗會只留在系統內。
