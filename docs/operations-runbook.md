# 歲悅電子公文交換系統營運 Runbook

版本：2026-05-23  
責任單位：總管理處、行政部、各部門主管

## 1. 每日營運作業

| 時間 | 作業 | 責任人 | 系統位置 | 輸出 |
|---|---|---|---|---|
| 08:30 | 每日收文拉取 | 總務 | 收文管理 / 背景任務 | 收文主檔、附件清冊 |
| 09:00 | 發文翌日查核 | 行政部主任 | 稽催追蹤 / 背景任務 | 未收確認、退回補正 |
| 09:30 | 交換失敗處理 | 總務 | 發文管理 / 維運中心 | 重送紀錄、通知紀錄 |
| 10:00 | Token 與憑證檢查 | 行政部主任 | jAgent 介接 / 資安控管 | Token 狀態、登入紀錄 |
| 18:00 | 歸檔封存與報表產生 | 主任 | 歸檔保存 / 報表統計 | 保存包、日報 |

## 2. 收文 SOP

1. 確認 jAgent 憑證登入與 Token 有效。
2. 執行「每日收文拉取」或手動拉取。
3. 檢查來文文號、文別、速別、密等、主旨、機關代碼、附件清冊。
4. 登錄收文號與保存年限。
5. 由總務分發給各部門主管；主管再指派業務助理或部門窗口處理。
6. 若發現誤送、漏送或附件不一致，建立異常通知並留存交換事件。

資料隔離規則：

- 總務只看總務收文入口、待登錄、待分發與自己負責的交換案件。
- 行政部主任只看行政部清稿、簽核、維運與授權案件。
- 總務與行政部主任不得直接檢視彼此部門公文；跨部門作業必須透過分派、會辦、簽核或授權紀錄。

## 3. 發文 SOP

1. 業務助理建立函稿與附件清冊。
2. 行政部主任執行清稿檢核。
3. 若需用印，依簽核流程核准後產生押章 PDF。
4. 系統保留押章前、押章後版本與檔案雜湊。
5. 封裝附件並送交 jAgent。
6. 次工作日執行收文確認與異常重送。

## 4. 交換失敗 SOP

1. 到維運中心查詢錯誤碼。
2. 檢查受文者機關代碼、交換中心、附件大小、附件雜湊、封包格式。
3. 若為 Token、憑證或交換中心連線問題，由行政部主任處理。
4. 若為附件或文書格式問題，退回業務助理補正。
5. 補正後由總務重送。
6. 通知中心需留下 Email、LINE、站內通知或派送失敗紀錄。

## 5. 備份與復原

- SQLite 本機測試：使用 `/api/actions/backup` 或維運中心資料備份。
- Supabase 正式環境：使用 Supabase PITR、scheduled dump 或管理後台備份。
- 每月應於測試環境執行復原演練一次。
- 復原演練需記錄 RTO、RPO、資料筆數、附件雜湊抽驗結果。

## 6. 變更管理

任何正式環境變更需留下：

- Git commit 或 Pull Request
- 需求來源與核准人
- migration 清單
- production readiness 結果
- rollback 方案
- 上線後 smoke test 結果

## 7. 交接清單

- GitHub repo 權限
- Vercel project 與 production env
- Supabase project、migration 與備份權限
- jAgent 正式 API 文件、交換中心資訊、憑證卡管理人
- SMTP 與 LINE webhook 管理人
- 主任與行政部主任簽核流程
