# 操作連續性改善與驗收

## 範圍與基準

首頁、撰寫公文、電子用印、簽核紀錄、收發管理、系統設定六頁。
以 Finance 的既有配色、Header、側欄為視覺基準；不改品牌、不增加功能層級。
正式電子公文交換 provider、權限、簽核關卡與正式資料均不在變更範圍。

## 問題與方法

1. 同頁與返回列表無條件跳頂：改為 session 內各頁捲動記憶，變頁將焦點帶至標題。
2. 同一查詢重複請求：合併進行中讀取，保留不同 query、cursor、帳號與權限邊界。
3. 背景初始化一次執行過多同步函式：依原順序分批，讓出主執行緒。
4. 未變組織資料仍重畫：比較正規化實際內容；同步時間可更新，控制項不重建。
5. 中文組字停頓時送出半成品：composition 期間暫停保存；完成後合併預覽與保存。
6. 列表背景更新與預覽重建移除焦點：未變內容保留節點，必要更新恢復相同案件操作。
7. 前一則提示計時提前關閉新提示：單一計時器，四秒顯示，hover 暫停。
8. 收文／合約視窗未隔離背景：共用焦點圍欄與背景 inert；不解除登入防護。
9. 每秒重寫未變 Header 狀態：內容相同不寫 DOM，減少朗讀與重繪。
10. 舊帳號同步回應混用新憑證：綁定實際 session／token／operation，登出即解除舊 busy。
11. 分批初始化清空剛輸入的合約：比對起始欄位快照，已修改時不再帶入空白預設。
12. 簽核視窗延後 focus 搶回新頁面焦點：開關視窗立即處理 focus，不留下舊 callback。
13. 組字或換登入期間列印舊預覽：列印前、字體等待後與下一影格均檢查輸入及 session。

## 驗收方式

- localhost 去識別化資料，修改前後相同六頁／桌機與手機截圖與視覺板。
- 真實瀏覽器檢查 route scroll/focus、modal/drawer keyboard、loading/retry、IME
  事件、列表焦點，以及無 console error／橫向溢出。
- 六身份 × 電腦、平板、手機既有流程測試；衝突版本與跨公司拒絕保持有效。
- 既有 Node/Python、PDF 操作與簽核輸出流程回歸通過後，才建立發布 PR。
- 正式發布證據：部署 READY、網域對應同一 SHA、靜態檔雜湊相符、health/readiness、
  未登入與私有檔案拒絕。正式頁面唯讀檢查，不建立測試公文、不呼叫正式交換機關。
