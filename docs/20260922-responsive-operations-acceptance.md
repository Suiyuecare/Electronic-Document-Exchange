# 上傳與操作順暢度改善

## 範圍與安全

電子用印進入工作區、選取 PDF、上傳與同頁編輯優先；桌機 1440×1000、手機 390×844。使用去識別化的合成 PDF、帳號與印章。正式資料唯讀，不更動公司印章或正式案件，不呼叫正式電子公文交換。

## 已確認瓶頸與驗收標準

| 問題 | 改善方式 | 驗收標準 |
| --- | --- | --- |
| 選工具／加字／保存會重畫同一 PDF 底圖 | 重用同一文件、頁面、倍率與版本的已完成／進行中繪圖 | 同頁 20 次操作不再產生 20 次底圖 render；換頁、縮放、版本與登入範圍改變仍重畫；失敗可重試 |
| 建立草稿後才開始本機檔案雜湊 | 並行準備，兩者成功後才申請上傳 | 不增加草稿／intent mutation；任一失敗或切換案件不得繼續使用舊回應 |
| 上傳尚在準備時就顯示 TUS 0% | 區分準備、實際傳輸、安全檢查與載入 | 百分比只反映真實傳輸位元組，未完成檢查不顯示成功 |
| 工作區讀取互相無關資料仍逐一等待 | 目錄／流程並行；只讀目前功能需要的印章資料 | 控制延遲下 round trip 明顯減少；同路由連點共用進行中讀取，不能誤當作已載入 |
| 「我的案件」先讀整批案件的關聯資料 | 把既有篩選提前交給伺服器，保留原 ACL | 同合成 100 件資料中只屬於申請人 1 件時，回傳內容／權限相同且 REST 呼叫由 401 降至 5 |
| 每次上傳前清理查詢及衝突時檔案驗證重複 | 清理合併有界查詢，衝突復用同次不可變檔案讀取 | 無待清資料 5 次查詢降至 1；衝突下載 2 次降至 1；到期／lease／CAS、檔案雜湊檢核不變 |
| 合法掃描 PDF 的圖片編碼偶然含 `/JS` 而被誤擋 | 以解析後的完整可達物件結構判斷，無法解析時仍拒絕 | 同一份 2 MB 合成掃描 PDF 可上傳；真正腳本、跳脫名稱、間接／壓縮物件、簽章與 XFA 仍拒絕 |
| 快速跨頁時設定仍在讀取，但第二頁誤當完成 | 共用同一登入範圍的設定載入；失敗可明確重試 | 不以舊版本取得簽核結果，不把業務缺件當網路故障；切換帳號不得套用舊回應 |

不以快取授權、跳過 readiness、防毒、檔案完整性或原稿不可變檢查換取速度。不把控制延遲或本機合成資料的時間，宣稱為正式站所有網路與檔案的 SLA。

## 介面與驗證

- 使用 UI/UX 簡化技能的非阻塞狀態模式：工作區讀取保留已可使用內容，簡短狀態列與失敗重試，不覆蓋整頁。
- Before 與 After 使用同份合成資料及固定延遲；比對可見回饋、PDF render 次數、API 數量、耗時、桌機／手機溢出及錯誤。
- 原簽核、權限、草稿、下載及檔案安全測試全部保留；任何測試略過須明列環境限制。
- 本文件為改善與驗收計畫；不等同已發布。正式部署需使用者確認與發布檢查通過。
